# 青禾 · C# 康养监测 0.3.2

.NET 8 / WPF 桌面应用。界面、视频采集、ONNX 推理、跟踪、雷达串口、档案、事件和报告均在 C# 中运行，无需 Python、浏览器或 Node.js。

## 使用

双击 `CareMonitor-0.3.2-embedded-win-x64/CareMonitor.exe`，或解压同名 ZIP 中唯一的 EXE。模型、图标、原生 DLL 和 .NET 运行时全部内嵌，可以只复制一个 EXE 到任意普通文件夹使用，适用于 Windows 10/11 x64，无需安装 .NET。

首次运行自动释放到 **EXE 所在文件夹下的 `Runtime\0.3.2-<资源哈希>`**，始终以 EXE 位置为准。准备过程中显示进度，可取消。后续启动校验并复用缓存，缺失或损坏时自动修复。移动整个程序文件夹后可继续复用资源；只移动 EXE 时会在新的位置重新释放。请把 EXE 放在可写的文件夹。资源按版本隔离，住户档案与设置保留在原位置。无须联网下载或管理员权限。说明及第三方许可也随资源释放。软件启动时不会自动打开摄像头、连接雷达或调用外部 API。打包机制见 `docs/embedded_desktop_20261010.md`。

“监控中心 → 打开视频”可直接测试。支持暂停、继续、时间轴、重播、拖入视频文件、USB 摄像头及 RTSP/HTTP 网络视频。网络地址只用于本次连接，不存入配置。按唯一设备标识选择 C60E，640×480、30 FPS，显示实际采集帧率。首次模型加载和推理需要预热，耗时与设备相关。先停止其他软件对摄像头的占用。

本轮已修正 DirectShow 重设尺寸/FPS 后丢失 MJPEG 的问题，两台真实 C60E 开启 RTMO + GMD 后同时约 30.3 FPS；人员分析与视频采集速度不同。实机 SR112 接收约 11.2 Hz、无帧号间隙。仍未完成实际双目标定，当前高度 TLV 未实收。0.3.0曾在四段GMD回放中漏检一段，0.3.1连续采样后这四段2跌倒/2正常均符合视频级标签；扩大至14段公开开发视频后，7段跌倒检出4段、漏检3段，7段正常无误报。见 `docs/recognition_repair_20261011.md`，不等于现场准确率验收。

“系统设置 → 跌倒检测模型”提供早期 GMD 二分类（默认）和增强二分类 Stage C（可选）。保存后重启软件生效。模型选择与人员检测/姿态方案独立，支持 CPU。云端训练已停止，软件不会触发训练或自动替换权重。

## 已实现功能

- 八个入口：监控中心、雷达监测、住户管理、事件记录、健康报告、系统设置、监测规则、双目定位。绿色与白色为主，实心内容底色，Fluent 图标。
- 默认 RTMO-m 同时输出人体框和 17 点二维姿态，会话内一对一位置、关键点与颜色跟踪，短时缺失恢复，最多同时分析6人；SSD基线保留ByteTrack.NET。原画面只画框，可靠关键点用于收紧人体框和去除重复框。低分检测只续接现有轨迹，编号不等于真实身份。
- R3D 二分类负责跌倒分析。稳定单人窗口保留原训练画幅；含其他人员的窗口使用独立裁剪，不把场景高分分配给某一人。详情不会因刷新、短时缺失或切页自动收起。
- 站姿、坐姿、躺姿、弯腰、蹲姿与行走使用宽高比修正和按秒稳定的二维姿态观测；坐下/起身单独显示短时转换。缺少关键点后旧姿态在 0.65 秒内过期。姿态独立于跌倒分值更新，快速下降后水平躯干可产生单独的动作异常证据；这些不是训练得到的多类概率。未通过回归的 NTU60、YOLO 和 VideoMAE 候选不进入发布包。
- 活动轨迹、停留热图、姿态时长、区域进入/离开、停留提醒和位置长时间静止提醒。“绘制区域”在视频上框选后填写名称与阈值，监控页可直接选中、删除、重新框选、取消绘制；“监测规则”可编辑删除、配置静止阈值和提示音。缺帧/遮挡不计入静止或停留时长。
- 事件保留视频位置，可定位当前已打开的视频；人工确认/排除、备注、CSV 导出和 JSON 观测导出。回放与现场分开，回放不发现场提示音。
- 双目定位提供两路实时预览、软件时间配对、棋盘采样和标定、跨视角多人匹配及三角化；米制定位仅使用与当前设备和分辨率相符的标定。没有标定时不输出三维坐标。普通 USB 双摄并非硬件同步；配对差超过 80 ms、关节不可见或对应有歧义时拒绝相应测量。
- SR112 双串口自动识别、固件检查、内置 AOP 基础配置与安装参数；真实点云、Doppler/SNR、轨迹/速度/加速度、体征与波形、提前存在标志、空间区域、活动与静息统计、观测 JSON 导出。1011 明确保留为前帧点关联；1012 高度和基于高度的异常规则只在收到相应包时启用。内置体征固件最多一个跟踪目标，无有效信号不生成体征数值。
- 住户、房间、床位与照护备注的增删改查，雷达目标手动绑定，本机原子保存和备份。
- 本地监测报告、OpenAI 兼容 API、Ollama/LocalAI 地址预设、可选定时报告、历史报告与 HTML 导出，入口在系统设置。本机 loopback 服务可不填密钥，远程服务需要密钥，Windows DPAPI 加密。API 只发送观测摘要，不发原视频、帧图、姓名或联系方式。

档案在 `%LOCALAPPDATA%/CareMonitor`，当前 JSON 存储适合本机项目规模，体征旧批次归档。

## 实测与限制

同口径 C# 滑窗复测 GMD Subject 4 的 37 段开发验证：Stage C 检出 17/17 段跌倒，误报 3/20 段日常活动；早期 GMD 检出 13/17，误报 0/20。整段至少两窗分数 ≥0.5 判阳性，不能当作机构现场、多人与暗光准确率。既有用户回归视频显示两模型各有优劣，可在设置中选择早期权重。方法见 `docs/binary_fall_selection_20261009.md`。

跌倒分析至少积累 2 秒、8 帧观测再启动，窗口按时间保留最近 5 秒。人员识别约按 8 Hz 调度，实际频率取决于硬件；视频显示与识别分别运行。首次预热在模型初始化时完成。检测或分类的可恢复错误会重试并清除过期结果。倒地后仍可能漏定位，此时保留场景疑似跌倒待定位提示，画面中能识别人但未定位到风险对象时也会提示。

多人裁剪、真实夜间和连续事件仍需现场验证。合成暗光、局部裁剪和拼接双人测试只属于回归，不能当作这些场景的真实准确率。设备体征未完成医学精度验证，静止/躺姿不等于睡眠分期；雷达与视频未完成空间配准。

此前 Stage C 方案实际实时回放七段跌倒与七段日常活动：RTMO 及实时处理链路检出 7/7、误报 1/7，对照链路检出 6/7、误报 3/7。这是已知公开开发片段，不能代表现场准确率；包含预热与窗口处理的改变，不是单独模型权重的提升。剩余误报为日常躺下，部分坐姿、俯视与出画动作仍难确认。完整方法和证据见 `docs/realtime_recognition_20261010.md`。

研究构建保留 RF-DETR/RTMPose 对照，发布包省去这些额外权重；保留 RTMO 和两套 R3D 选择以及 SSD 基线。

## 开发与来源

导出与评测工具用 Python，应用运行不用 Python。`scripts/export_desktop_models.py` 保留 Stage C 默认；`scripts/export_binary_fall.py --checkpoint artifacts/gmdcsa24_r3d18_100ep_inference.pt --name gmd` 导出早期对照。`scripts/prepare_open_source_models.py` 准备实时模型与固定 ByteTrack 源码，保留已记录的本地内存上限改动。

```powershell
$env:DOTNET_CLI_HOME='D:/dachaung/desktop/.dotnet'
$env:NUGET_PACKAGES='D:/dachaung/desktop/.nuget'
$env:MSBuildEnableWorkloadResolver='false'
dotnet build desktop/CareMonitor/CareMonitor.csproj -c Release --source D:/dachaung/desktop/packages
.\desktop\publish.ps1
```

发布要求新目录，避免混入旧 Preview 模型或测试数据。许可、版本、哈希和修改记录在 `Assets/Notices` 与模型旁 JSON。来源：[RTMO](https://github.com/open-mmlab/mmpose/tree/v1.3.2/projects/rtmo)、[RF-DETR](https://github.com/roboflow/rf-detr) 与 [RTMPose](https://github.com/open-mmlab/mmpose/tree/v1.3.2/projects/rtmpose) 对照、[ByteTrack.NET](https://github.com/arturbuszka/ByteTrack.NET)。Fluent System Icons 为 MIT。

## 双目与雷达操作

系统设置中保存 GMD 和 RTMO，重启后生效。双目定位页选择两台不同 C60E，点击连接；主监测沿用左相机，右相机提供辅助姿态。摄像头摆放或分辨率改变须重新标定。可打印 Assets/Radar/stereo-chessboard-25mm.svg（A4 横向，100% 比例，格长 25 mm），采集至少 12 组不同位置、距离和倾斜角度的棋盘。角点在内存中保留，不保存照片；标定参数保存到原档案目录的 stereo-calibration.json。

系统设置中点击雷达自动识别、检查固件、初始化并连接。安装高度和角度需按现场填写。设备若已经按匹配配置运行，可在雷达监测直接连接数据口，避免重复初始化。当前固件不是所有例程的集合；手势、ADC、热图等其他例程的数据没有收到时不会显示为实测。当前已实收 1010/1011/1020/1021/1040，未收到 1012。区域使用雷达跟踪坐标填写；丢目标不等于离床，静息时长不等于睡眠时长。功能来源及验证见 docs/device_upgrade_20261010.md。


## 0.3.1 使用变化

健康报告支持原生排版、复制正文、折叠依据与HTML导出；系统设置的智能分析服务提供测试连接及单独保存。监控中心直接选择或点击区域后删除、重新框选；取消按钮和Esc退出绘制。双目定位按右侧1–3步完成首次标定；附带10×7格棋盘对应9×6内角点。[标定说明](../docs/stereo_calibration_guide.md)和[修复记录](../docs/recognition_repair_20261011.md)。

新版本继续单EXE发行，业务资源首次释放到EXE旁Runtime目录；档案、密钥和真实标定仍保存在原用户数据目录。

2026-10-11清理旧发行包后新增0.3.2；交付使用0.3.2发行包。旧validation程序和bin/obj已删除，设备验收脚本按需从当前源码构建；模型校验基准独立保存，不需要旧安装包。[清理记录](../docs/project_cleanup_20261011.md)。

## 0.3.2 检测更新

最近5秒主窗口之外增加有动作与位置支持的2秒复核，短窗口连续两次阳性才参与判断；长短分值在人员详情、导出和报告中分别显示。14段已知公开开发回放：7段跌倒检出6段（0.3.1为4段），7段正常无误报；扩大到Subject4全部20段正常活动后无跌倒误报。两组正常片段有重叠。仍漏检Fall09，三段正常活动仍出现多余人员框；这不是独立泛化准确率，也没有重训权重。方法及最终验证见 [双时间尺度复核](../docs/model_optimization_20261011.md)。
