# 雷达与生命体征前端补齐（2026-10-08）

本轮在现有绿白医疗工作台中实现独立雷达观察页，复用 Three.js 空间画布和 Recharts，不新增依赖；视频跌倒模型和训练权重保持现有运行版本。

**最新状态：** 2026-10-08 后续已通过 CP2105 COM8 / 921600 接入真实雷达，网页实际点云、轨迹与两条动态体征波形通过浏览器验收。原文离线状态、旧 PID 和缺 pyserial 记录仅描述早期验收，最新运行与复现见 [CP2105 接入记录](sr112_connection_20261008.md)。同时修复失效登录仍显示无数据工作台的问题，增加媒体重试及独立标记的页面演示。

## 页面和入口

- 左侧“雷达与体征”：实测三维点云、XY 平面轨迹、目标选择、位置/距离/速度、固件可信度、心率/呼吸率、两类波形、实收趋势、串口和帧状态。
- 监测台下方“雷达观察台”入口：读数受来源、目标存在性和 3 秒有效期约束。
- “设备与数据”：视频与雷达的实际状态替换演示设备目录，保留真实/模拟/MMFi/录制回放的数据源切换。
- “系统设置”：已有大模型 API 配置入口保持可用。

内容区采用不透明白底、绿色线条、直角分隔和小半径控制。手机 390px 布局单列，宽表仅在表内部滚动。

## 数据通路与限制

认证 `GET /api/edge/radar` 只读 `RadarPhaseProvider` 缓存，不读串口或消费待广播体征队列。原 `/api/edge/point-cloud` 仍兼容视频空间模块。

快照提供数据源/会话、端口/波特率/串口组件与错误、接收时间/年龄、帧编号/TLV 类型、最多 2048 点、最多 256 轨迹及原始体征。缓存整体替换；切源清空缓存/半帧并更换会话。默认固件配置实际只支持一个跟踪目标；浏览器用两个合成目标验证选择逻辑，不表示已验证实机多人能力。

1040 体征必须匹配同包轨迹，呼吸偏差为正。没有 1040 的后续轨迹帧保留上一体征，但不改原接收时间，也不重复计入趋势。目标离场、无效体征、串口异常清除相应缓存。3 秒过期时当前读数、波形和空间目标清空。请求挂起时前端本地时钟也检查有效期。

真实页 200ms 顺序轮询，其他页 1s，后台降低频率，切屏/退出中止旧请求。每目标轨迹/趋势最多各 120 条，按接收时间和帧编号去重，会话变化或离场清空。真实源采集循环改为 0.1s 间隔，并按串口已缓存字节批量读取；这不是实机吞吐实测，真实刷新率仍取决于固件、串口包量和读取超时。

波形显示当前包 15 个样本，横轴为样本序号，逐包更新。物理幅值单位与采样时序未核验，不拼接成心电图。固件可信度不是校准概率，质量评分未知；0.1m/s 体动阈值待标定。没有睡眠分期、AHI 或呼吸暂停诊断。

模拟/回放/MMFi 的体征在独立表格明确标源，不填充真实空间与波形。生产无设备时保持空值。
