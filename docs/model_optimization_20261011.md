# 双时间尺度跌倒复核 · 2026-10-11

本轮沿用既有GMD/Stage C R3D-18权重，优化应用的实时窗口与证据判定，没有新增训练、下载新模型或重启云端长训。单人画幅与多人独立裁剪保持原实现；两种窗口的原始分值分别保留。

## 问题与改动

0.3.1的14段已知公开开发回放为4TP、3FN、0FP、7TN。S4 Fall08/17能识别躺姿，但5秒窗口中的先前正常动作稀释了短暂跌倒；Fall09连姿态观测也不可靠，原视频分值很低。

增加最近2秒辅助窗口，由同一视频模型推理。仅在有前序动作与位置线索时请求额外推理，并要求连续两个短窗口阳性。5秒原分值、CAM和全景分值保持独立，个人原分值不改写为短窗口最大值。稳定直立姿态继续作为反证；多人各自记录短窗口，不转移全景或其他人的证据。

图像位置线索要求此前可信肩/髋/足部观测，随后肩部下降与躯干转平，人体框下沿接近此前支撑足位置。动作开始后的床上关节变化不能重新定义支撑位置。该线索有时间上限，在切源、断帧和重新站稳时重置；它不是米制地面标定、真实身份或医学诊断。辅助几何参数是在已知开发片段上调试的，不能据此证明跨场景泛化。

网页沿用其33关节观测，并额外要求原姿态TCN候选；按真实帧时间提取短窗口。分类线程仍只保留最新任务。界面、导出和报告显示长窗口分值、最近2秒分值及连续确认次数，原分值不被替换。修复网页人员读数把已确认短窗口再次覆盖为“模型分歧”的问题。

## 验证过程与界限

最初仅以躺姿辅助短窗口的方案，在14段公开回放中得到6TP/1FN/0FP/7TN，但扩大至20段正常活动后误报ADL10/15的躺床动作，因此没有发布。完整记录 `artifacts/model_optimization_20261011/replay_short_candidate.json` 和 `replay_adl20.json` 保留。

两次中间位置方案也未同时解决关键误报与漏检，报告 `four_supported.json`、`four_locked_support.json`、`four_anchor_final.json` 保留。本次最终位置方案的4段关键回放为2TP/2TN，见 `four_position_verified.json`，CPU/GPU模型数值、原功能与新增支撑边界自检通过。

最终真实回放已完成：14段公开片段为6TP/1FN/0FP/7TN，原0.3.1为4TP/3FN/0FP/7TN；Subject4全部20段正常活动为0FP/20TN，包括此前误报的正常躺床。两组包含6段相同的正常片段，不可把批次合计当成独立样本数量。仍漏检Subject4 Fall09。

此前授权的用户片段仅产生一次跌倒事件，时间为9.215673秒；0–8秒站立段无事件，全部181帧维持ID1。15段以及20段均在回放结束时完成末窗口分析，RGB结果时间与视频末时间一致。20段正常活动中的ADL05/07/10仍出现多余检测框，人员计数问题尚未解决。终态证据见 `replay_final15.json`、`replay_final_adl20.json` 和 `summary.json`。

CPU/GPU自检通过，网页后端67项测试和前端生产构建通过。既有14段、GMD Subject4与用户片段都属于已查看的开发回归，不是未见测试集或临床准确率。网页姿态辅助链路不同，本轮桌面检测数字不能直接套用到网页。源码与交付版本更新为0.3.2，最终内嵌包已通过完整资源释放/修复/移动、CPU/GPU自检及八页界面验收；人员短窗口详情、播放按钮与断开后关闭均通过。首次候选的播放按钮检查失败记录保留，修正后重新打包并验收。
