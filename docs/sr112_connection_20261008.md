# SR112 / CP2105 实机接入记录

2026-10-08。此前“只有蓝牙串口、无真实雷达”的记录已经过时。CP2105 已连接，配套运行配置已加载，项目与浏览器已收到真实点云、轨迹和固件体征波形。毫米波仍独立于视频主模型训练。

## 驱动、端口与固件

检查 `SR112/07-驱动/Windows` 中旧版与 Universal 驱动包，并核对 Windows PnP 属性：

| 接口 | 当前端口 | 波特率 | 状态 |
| --- | --- | --- | --- |
| CP2105 Enhanced，MI_00 | COM7 | 115200 | 控制 UART，Status OK / ProblemCode 0 |
| CP2105 Standard，MI_01 | COM8 | 921600 | 数据 UART，Status OK / ProblemCode 0 |

设备 VID/PID 为 `10C4:EA70`。两路均使用已签名的 Silicon Laboratories `oem138.inf` / **6.7.6.2130**。目录另有 Universal 驱动 INF **11.3.0.176**；设备已正常工作，本次没有重装驱动、执行注册表补丁或刷写固件。

COM7 的 `version` 查询返回 **IWR68XX AOP ES2 / SDK 03.05.00.04**；`help` 包含 `vitalsign` / `VSRangeIdxCfg`，与 AOP 生命体征例程相符。查询记录在 `artifacts/radar_research/com7_identification.json`。

## 首帧和安装参数

COM8 最初被动读取 5.093 秒收到 **0 字节**。这说明驱动和串口可用，但采集尚未启动。

加载供应商原始 `vital_signs_AOP_6m.cfg` 后，37 条命令均返回 Done；随后约 8 秒收到 **53,356 字节 / 91 个可解析帧**。包含 1020 点云、1010 轨迹、1011 关联、1021 信息和 1040 体征。解析器处理本次真实字节流，原始录包为 `artifacts/radar_research/com8_configured_capture.bin`，它不是合成测试夹具。

用户确认“1.8m 正对人”。据此生成独立配置：

`artifacts/radar_research/vital_signs_AOP_6m_height1p8.cfg`

仅将 `sensorPosition 2 0 15` 改为 `sensorPosition 1.8 0 0`，即高度 1.8m，按水平朝向处理；供应商原文件不修改。完整配置再次逐条通过。单独更新安装参数的一次尝试返回“首次启动必须完整配置”，已保留失败记录并通过重新加载完整配置解决；不能据此确定设备重置原因。

这只是设置用户报告的安装参数，不是位置、角度、体征精度或视频空间配准的实测标定。该配置最大一个跟踪目标，帧周期 90ms，体征刷新 15 帧 / 300 帧窗口。

## 项目接入与网页

已安装 `pyserial 3.5` 到项目 `.deps` 并写入后端依赖清单。DATA UART 先禁用 DTR/RTS，再打开；采集只读当前已收到的字节，避免小包等待 4KB 阻塞 API。`scripts/start_backend.ps1` 未设置 RADAR_PORT 时，只在唯一 CP2105 Standard 接口存在的情况下自动识别数据端口；不会自动加载控制配置。

当前后端使用 COM8 / 921600，数据源选择 **real**。C60E 后续按用户扩大视野要求改为 **640×480 / 4:3**，实际约 30 FPS。部署时发现其他工作已接入 `care_video_active_inference`，保留该当前权重，未降回旧视频权重。用户选择的回放源保持不变。

在 [本地网页](http://127.0.0.1:5173/) 登录后：

- “雷达与体征”：实测点云、位置轨迹、单目标详情、心率/呼吸率、两组各 15 个样本的波形、接收趋势和串口状态。
- “监测台”：点云视图切换至“雷达”可显示同一真实缓存；三维人体仍来自视频全身姿态，雷达不会代替缺失的视频骨架。
- 两处点云都有“稳定显示 / 原始点云”：稳定模式累积最多 500ms 实测回波，6cm 体素合并并抑制孤立点，不按点序号插值。处理只用于显示，不修改 API、数据库、体征或训练输入。点以高对比圆点绘制，首次按回波范围聚焦，后续保持用户视角；轨迹线加深至 3.5px。
- “设备与数据”：核对数据源为真实雷达。显式“开启演示”仅在本页面合成数据，始终标注，不进入后端/数据库/告警或摘要。

登录失效时返回登录页；媒体加载失败提供“重试画面”。测试通过真实鼠标操作验证，没有切换原有视频源，也没有保存摄像头图像。

## 证据与复现

- `artifacts/radar_research/project_live_validation.json`：50 次连续采样，50 个不同帧号，点云最多 149 点，单目标、真实体征和两组 15 样本波形；同期 C60E 30.2 FPS。
- `artifacts/page_data_recovery_validation.json`：雷达页真实点云及动态波形、监测台雷达点云、JWT 失效恢复、媒体中断与重试、390px 无横向溢出、无未捕获浏览器异常。
- `artifacts/radar_real_usable.png`：真实雷达页截图；`radar_demo_usable.png` 则是明确标注的演示截图。
- 最新 Python 全项目 **107 passed / exit 0**，串口/摄像头专项 **30 passed / exit 0**。全量在 Windows 沙箱退出阶段出现过原生 STATUS_INVALID_HANDLE；宿主隔离复跑通过，未将异常退出那次算成功。前端点云、空间与登录恢复自检、TypeScript 与 Vite 构建通过，保留既有大模块体积提示。

后续显示优化证据：`artifacts/c60e_fov_probe.json` 的背景特征匹配估算，640×480 相对原 640×360 的可见场景宽约 1.047 倍、高约 1.395 倍（291 个匹配内点），五个输出格式采集均约 30 FPS。1080p 并不扩展当前场景范围；数字变焦原已为 100（1x）。这是当前静态背景下的估算，不是光学视场角标定。

`cloud_processing_audit.json` 回放真实录包中的 91 帧，预热后原始点数变异系数 0.9447，优化后 0.6812，降低约 28%；只证明这段录包的点数闪烁减少，不等同位置精度提高。`uart_latency_after.json` 的 30 次请求看到 30 个不同快照，观测频率约 8.49Hz，最大 API 请求耗时 27.7ms；此前一次请求等待 207.9ms，两次采样节奏不同，不能直接比较中位延迟。同期 C60E 640×480 / 30.3 FPS。

用户最后要求以点云二次处理为主，不再改心率；后续保留固件心率和安装参数。静止场景实际有 1–4 点的稀疏帧，优化显示不能恢复未被设备测到的形状。500ms 累积可能出现短拖尾或丢掉孤立实测回波，可切原始点云对照。

USB 拔插或雷达断电后，运行配置可能丢失。需要使用供应商可视化器选择 Enhanced 控制口、Standard 数据口并加载上述 **1.8m 配置**，或逐条发送相同配置；应确认版本相符且所有命令返回 Done。GUI 与项目不能同时占用 DATA UART。项目重启后在“设备与数据”选择真实雷达。

启动变量可明确覆盖：

```powershell
$env:RADAR_PORT = 'COM8'
$env:RADAR_BAUD = '921600'
powershell -ExecutionPolicy Bypass -File .\scripts\start_backend.ps1
```

COM 编号可能随 USB 接口变化。重新枚举时以 Enhanced / Standard 接口身份为准，不能固定把任意 COM8 当雷达。

本轮没有固件烧录、驱动替换或云端训练修改。固件心率/呼吸率尚未与参考设备对照；波形幅值未标定，不能当心电图，缺失/弱信号仍保持缺值。没有新增睡眠分期、呼吸暂停诊断或 AHI。
