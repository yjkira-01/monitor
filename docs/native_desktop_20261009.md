# 原生 C# 桌面版开发与验收

用户要求以C#实现界面和业务，整包在Windows PC双击运行，并把演示档案/体征改为真实来源。本次创建了独立.NET8 WPF工程，保留原网页与正在使用的来源，不启动或重启旧服务，不打开摄像头、串口或发送硬件配置。

## 范围与实现

| 链路 | C#实现 | 当前实际来源与限制 |
|---|---|---|
| 文件/USB视频 | OpenCvSharp采集、原生WriteableBitmap与框绘制、暂停/时间轴/重连 | 无浏览器/Python服务；文件回放有独立测试标记 |
| RGB模型 | ONNX Runtime CPU或DirectML，16帧R3D，最多4个独立人物缓冲、2人轮转推理 | 保留Stage C基线；未部署Stage D/E候选 |
| 模型依据 | 全景空间响应CAM、512维特征余弦变化、窗口结束时间 | 中心区域的整窗弱解释，不能精确定位到个人，分数不是风险概率 |
| 姿态与辅助复核 | SSD COCO人物 + BlazePose Full真实33关节 + 48帧TCN | 7×7热图细化与可见度语义复用MediaPipe；旋转人物裁剪与原管线有差异 |
| 多人显示 | 原生GLB蒙皮、躯干/头部/四肢方向、缺失关节历史保持、多人视角适配 | 固定CC0体型、非人体形状重建；没有观测时不捏造目标 |
| 点云 | 有界原生3D几何，视频估计点集与雷达XYZ分开 | 视频点集明确非雷达实测，无视频/雷达时空配准 |
| 雷达 | SR112数据串口、控制串口配置ACK、UART录包，TLV1/1020/1010/1040 | 真实设备未连接验收；不是模拟生理值回填 |
| 体征/静息 | 同包轨迹+有效1040、波形、按目标选择趋势、体动/低体动样本 | 设备输出需独立精度验证；不推断睡眠分期、AHI或诊断 |
| 档案与事件 | 真实人员/房间/床位CRUD、搜索、人工绑定雷达目标、事件复核、CSV | 初始为空；跟踪编号不是身份；回放事件不计入现场预警 |
| 报告与API | 本地摘要、OpenAI兼容请求、可选定时、历史与HTML导出、DPAPI密钥 | 外部请求去掉文件名、实名、联系方式和视频；真实API供应商尚未验证 |
| 存储 | 当前Windows用户JSON原子保存/备份，旧体征/事件/报告归档 | 单机研究规模；机构规模数据库、权限及数据迁移未实现 |

## 打包与依赖

发布目标为Windows10/11 x64。包包含.NET运行时、ONNX、OpenCV、DirectML和应用本地VC运行库；VC文件来自微软官方`Microsoft.VCLibs.x64.14.00.Desktop.appx`，8个DLL的Authenticode签名均Valid，来源/hash在Assets及`artifacts/desktop_runtime_signatures.json`。未执行系统安装器。第三方许可与CC0资源出处保留。

当前SDK的NuGet HTTPS传输失败，而Python标准urllib可正常访问；`fetch_desktop_dependencies.py`准备常规本地feed后完成还原。运行程序不使用这个下载工具。`publish.ps1`生成目录、SHA256与便携ZIP，排除UI测试截图、测试档案、自检输出和PDB。

## 验证证据

`desktop_model_export_validation.json`记录PyTorch/ONNX对照。加入模型依据输出后，RGB概率最大误差2.79e-8，embedding1.91e-6，CAM2.38e-7；TCN与检测器也通过断言。此验证仅说明导出数值一致，不是准确度改善。

`desktop_gpu_validation.json`记录真实C#自检：分片与坏帧、1010/1040/NaN、JSON回读、重复床位、DPAPI、本机OpenAI协议和不发送档案姓名、33关节输出、公开测试视频、Python/C#169维特征、RGB与暗光预处理一致性、原生GLB。VC运行库实际从应用目录加载。CPU模式也执行了对照。

`desktop_ui_validation.json`记录原生窗口实际回归：公开视频持续更新、暂停、seek代次、stop/reopen、六页切换与截图。四人渲染验证复制同一公开姿态并明确标注，只验证显示容量，不证明真实多人识别。峰值间隔含截图和创建人物开销；不能将Dispatcher间隔当作显示器呈现FPS或低配稳定性保证。

实际公开样本末段人体到达画面边缘，人物检测仍可能丢失；界面保留全景跌倒分数与未定位复核事件。没有把这种漏检宣称为已解决。私人视频和摄像头帧图没有落盘。

## 未完成验收

## 0.1.1 原生界面与发布验收

用户要求改进按钮、应用图标及企业使用文案。已参考Fluent2官方Button/Iconography与WPFUI，使用本项目WPF模板，维持C#原生实现。统一5px按钮圆角、主/次/工具/删除样式、hover/press/disabled和可见键盘焦点；导航有图标和选中标记。微软MIT Fluent图标固定到cd332ec1f90cda2fad16f86754f8da52f1e9ab30，25个向量与许可/来源/哈希保留在Assets/FluentIcons；9尺寸ICO已写入exe资源，并由Windows Shell实际提取验证。

业务入口改为监控中心、生命体征、住户管理、告警记录、健康报告、系统设置。人员状态、监测结果、姿态视图、静息记录采用普通业务名称；主层显示状态和更新时间，分析分值/置信度/处理耗时在展开详情中查看。设置保留智能分析服务地址、分析模型、加密访问密钥和自动报告。界面不展示模拟生命体征，也不把视频估计点云当成雷达实测。

发布目录`desktop/release/CareMonitor-0.1.1-win-x64`，便携包`desktop/release/CareMonitor-win-x64.zip`。实际CPU和GPU自检均exit0，应用本地VC库加载、JSON/DPAPI、本机OpenAI兼容请求、公开视频120帧、Python/C#数值对照、49格CAM断言通过。Codex受限账户未加载DPAPI用户配置时自检失败，改为授权的真实Windows用户上下文后验证通过，没有降低加密范围或使用明文密钥。

最终原生窗口回归passed：436次计时更新、107个不同视频帧、41个姿态更新时间；5个实际导航点击、设备下拉菜单、编辑弹窗、1024px布局、停止按钮禁用、暂停/继续文字图标、seek及重开视频、窗口Icon均通过。p95计时器间隔109.91ms/max566.01ms，测试包含截图、模型初始化与多个人物创建，不能当成30FPS或长时流畅性验收。公开样本末段依旧丢失边缘人物，但全景疑似跌倒为1并提示核查；单人场景的最终截图为重开公开视频的实际一人结果。复制四个人体的截图仅作渲染测试（紧凑布局截图也沿用该测试渲染数据），不作为多人识别结果展示。

包内522项通过CRC，所有SHA256条目匹配，模型、OpenCV、DirectML、VC与.NET运行库及图标均存在，无UI截图、测试档案、自检输出或PDB。ZIP267244254字节，SHA256为ad211eca97c0c1bb8fa9ba2efd6b87e1081cd0a4a875f8950f1e03fc76732814。证据更新在artifacts/desktop_{gpu,cpu,ui,package}_validation.json及desktop_monitor_active.png、desktop_api_settings.png、desktop_exe_icon.png。实际USB摄像头枚举仅Integrated/OBS，当前未看到EMEET，因此没有宣称C60E接入验收。
