# 0.3.1 识别、报告和交互修复记录

## 已定位的问题

用户提供约12秒的问题片段，在0.3.0回放中同一人被分成编号1、4、7、9；末段整体分值接近1，新编号没有足够RGB历史，个人状态没有同步。桌面仅按姿态分析节奏采样视频，而早期网页按采集帧积累窗口；EOF没有明确提交末窗。纯文本报告框直接显示大模型Markdown标记。日志确认已断开设备后关闭窗口触发WPF Closing重入。

## 实现

- 保留早期GMD二分类权重及原始分值；捕获帧构成有界5秒窗口，视频结束提交最后一窗，回放验收等待对应RGB结果。
- RTMO轨迹改为会话内一对一位置、关节和颜色关联；短时缺失恢复历史，同屏多人分开关联，有歧义或超过2.5秒时不冒用旧身份。非生物识别，不能自动绑定住户。
- 直立姿态使用伸展膝与腿方向，减少透视下肢缩短造成的unknown。姿态置信度根据可见侧和腿部支持计算。可靠直立与高视频分值冲突时显示结果待复核，原始分值仍保留；倒地、局部人体、动作异常不被直立规则过滤。该逻辑是观测复核，不是重新训练出的概率。
- 单个高分窗口而没有支持姿态时等待连续确认；高分与可靠躺姿/倒地观测一致时可在首个窗口提示。低视频分值与躺姿本身不能直接认定跌倒，正常躺下仍须区分。
- 原生报告标题、列表、加粗排版，历史报告兼容。观测依据折叠，复制为纯文本，HTML导出安全排版。API支持根地址、/v1或完整接口；连接测试、专用设置保存、等待时间、取消、明确错误及超时。非接触雷达语义与历史告警时间进入摘要。
- 监控页直接选中、修改、重新框选、删除区域，取消绘制和Delete键生效；清空仅作用于当前来源。人员框覆盖区域或脚点进入都可统计，缺失期间不累计停留，删除后清除旧状态。
- 雷达点云使用真实输出坐标、米制网格、径向速度/SNR着色、目标标签与轨迹，支持俯视、缩放、复位、适配范围。未知属性显示灰色；不把散射点补成虚构人体。按新雷达帧更新。
- 40px按钮与输入高度统一，清晰主次/删除按钮，减少圆角。
- 关闭流程退出原Closing事件后释放资源，再调度关闭；新增停止采集后关闭的验收。
- 双目标定提供贯穿页面的操作面板、棋盘保存、默认内角点说明、角点暂显、组数与覆盖进度、显式导出备份和有针对性的导入错误。

## 模型对照与限制

同一用户片段：GMD站立阶段分值也偏高；Stage C增强权重几乎全部为0，末窗约0.0001，没有响应跌倒。因此本次不自动切换Stage C，也不通过取两者最大值声称优化。后续判定必须同时检查站立误报、真实倒地的时间轴和其他正常/跌倒场景，不能只看整段predicted_fall=true。

当前修改没有启动云训练、修改模型参数或声称所有场景准确。实机双目标定尚需用户打印棋盘完成；SR112当前固件仍最多一个体征目标。本轮设备协议和安装配置保留，不反复初始化正在工作的雷达。

验证证据在 artifacts/recognition_repair_20261010；最终发布包验证结果见下文。
