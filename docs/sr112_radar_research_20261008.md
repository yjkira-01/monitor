SR112 是系列名称，手册同时覆盖 60–64 GHz 的 IWR6843AOP 和 77 GHz 的 IWR1843AOP。项目现有代码与选定固件走 **60 GHz / IWR6843AOP**；实机型号仍须依据板上标识核对，不能仅凭资料目录判定。该板通过 Type-C 供电与通信，CP2105 提供两个 UART：Enhanced 为控制/烧录口，Standard 为数据口。COM 编号不是固定值。配套 Python GUI 对 xWR6843 使用控制口 115200、数据口 921600。

本机只读枚举看到 COM3、COM4、COM5、COM6，均为蓝牙串口，未看到 CP210x 双串口。因此本轮没有打开雷达串口、发送配置或烧录固件。

## 协议与已经修复的代码

确认的 40 字节帧头是 `<8s8I`：魔数、版本、总长度、平台、帧号、CPU 时钟、检测点数、TLV 数、子帧号。总长度位于偏移 12，TLV 数位于偏移 32。TLV 头是 `<II`，长度只包括载荷。配套解析器按 32 字节填充检查帧总长度。

| TLV | 载荷布局 | 本轮实现 |
| --- | --- | --- |
| 1 | 每点 `<4f>`：x、y、z、径向速度；点数来自帧头 | 修复多读计数字段的问题，保留项目 xyz 视图 |
| 1020 | `<5f>` 解压单位 + 每点 `<bbhHH>`：俯仰、方位、速度、距离、SNR | 解压带符号角度并转换成雷达 xyz 坐标 |
| 1010 | 每轨迹 `<I27f>`，112 字节 | 保留目标 ID、位置、速度、加速度与固件置信度字段 |
| 1040 | `<HH33f>`，136 字节 | 目标 ID、距离 bin、呼吸偏差、心率、呼吸率、各 15 点波形 |

未实现的 TLV 不伪造为已解析数据。其中 1011 的点关联对应前一帧，不能直接拼给当前点云；本轮没有做这种关联，也没有将雷达 ID 等同老人身份。主页面点云继续只展示 xyz，径向速度/SNR 暂未作为页面点属性输出。其他帧头/SDK 格式仍需对应固件资料验证。

本轮修复的主要错误：

1. `edge/capture_oob.py` 曾从偏移 8 读取总长度，实际读到版本号。现在与后端共用解析器。
2. 原 type 1 解析和人工夹具错误地假定载荷以点数开头。已改成 SDK3 格式，并重新生成明确标注为合成的测试夹具。
3. 原串口读取在拿到完整帧后清空所有缓冲，丢弃尾部半帧；也仅使用最后一帧。新 `consume_frames` 消费完整帧并保留半帧/跨 read 魔数，校验长度、载荷尺寸与非有限数，坏帧可重新同步。
4. 原 `RadarPhaseProvider` 以点云平均距离充当胸腔相位，再计算心率/呼吸。该路径已移除；只有点云时仍更新点云，但体征返回缺失。
5. 原缺硬件时自动使用合成相位，并把输出标为 `real`。默认真实源现在保持无数据；显式合成源标为 `mock`。
6. 原距离振幅直接写入 `chest_displacement_mm`。在没有相位/位移单位标定时该字段保持空；`ahi_index` 也保持空。
7. 固件体征附带波形、目标和待复核信息。真实数据落库现在只传数据库列，广播保留附加元数据，避免因 `quality` 等非数据库字段造成构造错误。仅有真实点云时也刷新雷达心跳。

真实体征只接受同一有效包内存在对应轨迹、呼吸偏差大于零的 TLV 1040，不重复广播已消费的体征；患者不存在或数据过期时不继续提供旧值。借鉴官方 GUI 的 0.02 呼吸偏差规则，仅将弱呼吸率置空并标待复核，**不作呼吸暂停诊断**。固件没有提供本项目标定的质量概率，`quality` / `vital_agreement` 保持空，`needs_review=true`。轨迹速度达到 0.1m/s 的体动标记是待标定工程规则，不是已验证的运动质量判据。

## 康养与睡眠开发路线

| 功能 | 数据与验证方式 | 当前边界 |
| --- | --- | --- |
| 真实三维点云/人员位置 | TLV 1020 / 1010，与已知位置和实测距离对照 | 当前页面雷达坐标，尚未与 C60E 标定 |
| 在床/离床、区域停留 | 安装姿态与床位空间边界、连续轨迹、现场标注 | 需要实际房间和床位标定；丢跟踪不等于离床 |
| 体动与夜间活动次数 | 轨迹运动，后续结合微动/波形质量及人工记录 | 翻身未必造成质心变化，速度规则不等于翻身分类 |
| 呼吸/心率趋势与波形 | 专用固件输出，对照呼吸记录/心率参考设备 | 已完成解析，尚未实机对照；缺值保持缺值 |
| 静息/疑似入睡与离床记录 | 持续在床、体动和有效呼吸趋势的规则，再做人工睡眠日志验证 | 先称静息或疑似入睡，避免把躺卧当确定睡眠 |
| 睡眠分期/呼吸暂停/AHI | 需对应参考标签与信号质量、专门算法及验证 | 本轮未开发，不凭单一弱呼吸阈值给诊断 |

优先顺序是串口首帧与配置核对 → 静止单人波形/参考体征对照 → 真实点云和轨迹展示 → 床位区域与夜间事件 → 经过标注的睡眠相关分析。毫米波暂不加入视频主训练；视频与雷达空间配准、时钟同步和逐人匹配应单独验证后再融合。
